# 塵界のそうじクエスト — 設計仕様書

最終更新: 2026-08-26 / 対象コミット: `c4cdb06`

この文書の用途は2つ。**(1)** 新しいセッションへの引き継ぎ、**(2)** 外部のAIや第三者にレビューを依頼するときにそのまま渡す資料。
実装を読まなくても判断できる粒度で書いてある。数値は実装から起こしたもので、推測は含まない。

---

## 1. これは何か

部屋の掃除が進まない人のための、一人用RPG。**ゴミを1個すてると経験値とゴールドが1増える。**

作者（利用者本人）は薬局の店長で、プログラマではない。自分ひとりで使うために作っている。

### 設計の最上位原則

以下は他のすべてに優先する。トレードオフが発生したら常にこちら側を選ぶ。

1. **最小の労力から始められること。** 「ゴミを1個すてる」がゲームとして成立する最小単位。これより小さい単位を作らない代わりに、これより大きい単位を必須にしない。
2. **習慣の継続そのものが目的。** ゲームが面白いかどうかは二の次で、明日も開くかどうかが評価軸。
3. **サボった人を罰しない。** 復帰した日にペナルティを与える設計は禁止。詳しくは §6.5。
4. **画面を縦に伸ばさない。** スマホでスクロールが増えると、それだけで開かなくなる。常設タスクを2つに絞っているのはこの理由（§6.1）。
5. **現実の報酬を混ぜない。** ゴールドの使い道はゲーム内の装備と鍛錬のみ。「10回掃除したらケーキ」のような外的報酬は意図的に排除している。

### 意図的にやっていないこと

レビュー時に「なぜ無いのか」と聞かれる前に列挙しておく。すべて検討した上で外している。

| 無いもの | 理由 |
|---|---|
| サーバー・アカウント・同期 | 端末内で完結させる。個人利用で、他人と比べる要素を入れたくない |
| 通知・リマインダー | 「催促されるアプリ」は消される。開きたくなる側で勝負する |
| カレンダーの直接読み取り | Webに該当APIが存在しない。iOSショートカット経由で代替（§6.9） |
| 連続日数が途切れたときのペナルティ | 原則3。途切れたことを責めない |
| 課金・広告 | 自分用 |
| 難易度設定 | 選ばせる時点で1手増える。敵の側を自分の強さから逆算する方式で代替（§6.4） |
| ソーシャル・ランキング | 比較対象は過去の自分だけ（§6.6） |
| ビルドツール・フレームワーク | 単一HTMLで完結させることで、5年後も動く可能性を上げる |

## 4. 実行環境の制約

ここを知らずに書くと必ず踏む。

### 4.1 iOS Safari

- **クロスサイト iframe の localStorage は消える。** §2 のとおり。検証は必ず実機の Safari で、ホーム画面に追加した状態で行う。Mac の Chrome で確認しても意味がない（過去にこれで誤判定した）。
- **`setInterval` は画面を消すと止まる。** カウントダウンを `left--` で実装してはいけない。実時刻から毎回引き直すこと:
  ```js
  var endAt = Date.now() + total * 1000;
  function sync(){ if(paused) return; left = Math.max(0, Math.ceil((endAt - Date.now()) / 1000)); }
  document.addEventListener("visibilitychange", onVis);
  window.addEventListener("focus", onVis);
  ```
  タイマーは「スマホを置いて実際に掃除する」ための中心機能なので、ここが壊れると製品として死ぬ。`startTimer` と `battleTimerRun` の2箇所にある。
- **入力欄の文字が16px未満だと自動でズームする。** バックアップ画面の貼り付け欄を16pxにしているのはこのため。
- **`navigator.vibrate` は非対応。** 呼んでも落ちないよう try/catch 済み。

### 4.2 Artifact の iframe（ミラー版のみ該当）

- `allow-modals` が無いので `confirm()` / `alert()` / `prompt()` が**エラーも出さずに無視される**。自前のオーバーレイ `ask()` を使うこと。
- クリップボード読み取り不可。バックアップの「貼り付け」ボタンは実装不可能なので、手動ペーストを `input`/`paste` イベントで自動検知する方式にしている。
- ダウンロード不可。ファイル保存ボタンは `window.top === window.self` で出し分けている（`canFile`）。

### 4.3 Service Worker

`stale-while-revalidate`。キャッシュを即返して裏で取り直すので、**更新は次に開いたときに反映される。** 検証時に「直したのに変わらない」ときはこれを疑う。キャッシュ名は `souji-quest`。

## 5. 保存データ

キー: `localStorage["souji-quest-v2"]` / 現行バージョン `v: 4`

```js
{
  v: 4,
  lv, xp, gold,                 // 成長
  day, dayCount, total,         // 今日の回数・通算回数
  streak, maxStreak, lastDay,   // 連続日数
  claimed,                      // デイリーボーナスを受け取った日
  tasks: [{ id, n, v, sec, w, h }],   // 常設タスク（既定2つ・ユーザー追加可）
                                // w:曜日[0=日..6=土] h:[開始時,終了時] どちらも任意（§6.8）
  items: [ …所持装備… ],         // 1点もの。最大80
  equip: { weapon, armor, glove, boots, acc },   // 装備中のアイテムid
  cleared: { e1: true, … },     // 撃破済みの敵
  log: [],  last: null,  seen: false,  hist: {},
  depth, maxDepth,              // 深層の到達階
  train: { atk, def, hp },      // 踏破後の無限強化
  dailyDone, dailyCount,        // 今日の魔物
  kills, timerSec, titles, dust,
  dayStart: 4,                  // 1日の区切り（既定 午前4時）
  dustDebt: 0,                  // 空けた日数（§6.5）
  ghosts: []                    // 過去の自分のスナップショット（§6.6）
}
```

### マイグレーション規約（事故の元）

`migrate(st)` は **読み込み時とバックアップ復元時の両方から呼ぶこと。** 片方だけに書くと、復元したときにだけデータが壊れる（実際に装備が全消滅した）。
新しいフィールドを足すときは `fresh()` と `migrate()` の両方に書く。片方だけだと、既存ユーザーだけ `undefined` で落ちる。

バックアップは JSON 文字列のコピー＆ペースト方式。本番URLで開いているときのみファイル保存/読み込みも使える。

### 1日の区切り

既定は**午前4時**。深夜0時で切ると、日をまたいで掃除した人の連続日数が理不尽に切れる。`dayStart` で 0〜6 時に変更可能。
区切りを変えた瞬間に記録が未来日付になって連続が切れないよう、`migrate()` で補正している。

## 6. ゲーム設計

### 6.1 タスク（常設2つ）

| | 名前 | 報酬 |
|---|---|---|
| `t1` | ゴミを1個すてる | +1 |
| `t7` | タイマー | 時間に応じて +1〜22 |

原則4により常設はこの2つだけ。ユーザーは作成フォームから自由に追加できる（時間 × 重さで報酬を自動計算）。
タイマーは 30秒/1分/3分/5分/10分/15分+ から選べ、報酬は 1/2/5/8/15/22。重さ係数は 軽い1.0 / ふつう1.2 / 重い1.5。

タップ時の当たり判定: 3% で「塵の中から何かを見つけた」+20G、12% で「会心」報酬3倍。
1日3回で**デイリー達成**（`GOAL = 3`）→ ボーナス `5 + (連続日数-1) * 2` G。

### 6.2 成長

```
必要経験値  need(lv) = 8 + (lv-1) * 5
HP    24 + (lv-1)*6  + 装備 + 鍛錬hp*10
こう   4 + (lv-1)*2  + 装備 + 鍛錬atk*2
まも   2 + round((lv-1)*1.5) + 装備 + 鍛錬def*2
鍛錬費  round(100 * 1.06^(鍛錬の総回数))    ※踏破後に解放・指数的に高くなる
```

### 6.3 戦闘（コマンド式）

ゲージが2本ある。**HP** と **気力**（最大5・開始1）。

| コマンド | 気力 | 効果 |
|---|---|---|
| はたく | 0 | 通常攻撃 `(こう - 敵まも*0.85) × 0.85〜1.15` |
| ゴミを拾う | 0 | **気力+2** ・ HP+8% ・ 戦利品が落ちやすくなる ・ EXP+1（1戦闘3回まで） |
| ためる | 1 | 次の一撃が `こう × 2.0`・敵のまもり無視 |
| 大掃除 | 5 | `こう × 2.6`・敵のまもり無視 |

> **気力は自然回復しない（`KI.REGEN = 0`）。これは意図的で、ゲーム全体の要。**
> 気力を得る唯一の手段が「ゴミを拾う」＝現実の掃除に対応するコマンドなので、強い技を使うには現実で手を動かす必要がある。
> 過去に自然回復を入れたところ、大掃除がほぼ無コストになって全戦闘の勝率が100%になり、ゲームが崩壊した。ここを触るときは必ず §8 を通すこと。

被ダメージ: `(敵こう - まも*0.60) × 0.85〜1.15`。会心は自分10%（+接辞）・敵6%。60ターン超過は敗北。

**戦闘中タイマー**: 戦闘画面から起動でき、走っている間は**被弾しない**。完走すると敵HPが最大25%減り、気力が全快する。
これが「スマホを置いて実際に掃除する」動線で、アプリの背骨。中断した場合も進んだ割合ぶんだけ効果が入る。

**おまかせAI**（`decide()`）: 過去に3回、瀕死の敵にとどめを刺さず回復し続けて自滅した。現在の形は
「①今すぐ倒せるなら殴る」を最優先し、回復は `heal > incoming * 1.15`（実際にダメージを上回るとき）に限定している。この順序を崩さないこと。

### 6.4 敵

- **ストーリー**: 5エリア19体。`AREAS` に固定値で持っている。前エリアのボスを倒すと次が開く。
- **今日の魔物**: 毎日1体。**今の自分のステータスから逆算**するので、いつ挑んでも手応えが同じ（`hp = こう × 6.0`）。難易度設定の代わり。
- **深層**: 踏破後に開く無限ダンジョン。ローグライク式で、HPを階に持ち越し、5階ごとに層主。3階ごとに**加護**（`BLESS` 20種）を1つ選ぶ。引き上げれば戦利品を持ち帰れ、倒れると全部失う。
- **宝を抱えた敵**: 12%（深層18%）で出現。HP1.3倍・ゴールド2倍・戦利品が必ず上質以上。

### 6.5 積もった塵（サボった日数が敵になる）

2日以上あいた翌日に、そうじタブの先頭にボスが出る。日数ぶんHPと報酬が増え、倒すと `dustDebt` がゼロに戻る。

```js
hard = min(days, 8)
hp  = こう × 5.0 × (1 + 0.04 * (hard - 1))
atk = HP/8 + まも*0.6            // 日数では強くならない
g   = こう × 1.4 × days           // 報酬だけは日数ぶん伸びる
```

> **難度の伸びを8日で頭打ちにし、攻撃力を日数で上げていないのは原則3による。**
> 最初の実装（HP係数5.6・攻撃力も日数で上昇）は8日以上で勝率50%まで落ち、実機テストで2連敗した。
> 戻ってきた人を跳ね返すのは設計意図と真逆なので、難度はほぼ据え置きにして、差は報酬側だけでつける方針に変えた。
> 現在は雑に殴っても90%以上勝てる。ここを「歯ごたえがない」という理由で上げてはいけない。

### 6.6 過去のあなた

週1で自動的にステータスのスナップショットを保存し、きろくタブから当時の自分に挑める。最大8体。
**戦利品は出ない**（`nodrop: true`）ので周回で稼げない。勝つと記録に残る。比較対象を他人ではなく過去の自分に閉じるための機能。

### 6.7 ハクスラ

装備は全部**1点もの**。同じ名前でも数値が違う。

- **5スロット**: ぶき / よろい / てぶくろ / はきもの / おまもり
- **レア度4段+伝説**: 並(×1.00) / 上質な(×1.12) / 業物の(×1.28) / 銘品・(×1.45) / 伝説（ユニーク5点・ボス専用）
- **接辞22種**: 通常16種＋**代償つき6種**（捨て身・重装・軽装・一点集中・前のめり・燃焼）。代償つきは「与ダメ+25%／被ダメ+18%」のように良い面と悪い面がセット。ビルドの分岐点はここ。
- **スロット別の偏り**（`SLOT_AFFIX`）: ぶきには会心・鋭さ・連撃、よろいには頑丈・守勢…と出やすい接辞が違うので、狙って集められる。
- **ドロップ率**: 通常40% / ボス100% / 深層55%。**「ゴミを拾う」を押すほど上がる**（`0.4 + 0.3 × 拾った回数`、上限1.3倍）。ここでも現実の掃除がゲームに効く。
- **後処理**: 売却 / 分解して塵の粉 / 引き直し（12粉）/ 格上げ（25粉）/ 強化 +N（1段ごとに数値+5%）
- 持ち物は80点まで。あふれたら弱い方を自動で売る。

装備の全数値はネタバレありのカタログ `docs/equipment-guide.html` に出してある（`node docs/build-guide.js` で実装から自動生成）。


### 6.8 タスクの予定（曜日・時間帯）

タスクに任意で**曜日**（`w`）と**時間帯**（`h`）を持たせられる。該当する時間になると、そうじタブの
いちばん上に「いま」欄が出てそのタスクが並ぶ。該当が無ければ**欄ごと出ない**ので、画面は伸びない（原則4）。

時間帯は6つのプリセット。いつでも / 朝 5-11 / 昼 11-16 / 夕方 16-19 / 夜 19-24 / 深夜 0-5。
曜日を選ばなければ毎日。両方とも未設定なら「予定なし」で、「いま」欄には出ない。

判定の注意点が2つある。

- **曜日は4時区切りで見る**（`shifted(0).getDay()`）。水曜の深夜2時は「火曜」として判定される。連続日数など他の日付処理と揃えるため。
- **時刻は実際の時計で見る**（`new Date().getHours()`）。深夜帯 `[0,5]` のように開始 > 終了の帯は日をまたぐものとして扱う。

**過ぎても何も言わない。** 時間を逃したことを責める表示は入れない（原則3）。
`setInterval` で1分ごと、および `visibilitychange`/`focus` で該当集合が変わったかだけ見て描き直す。

判定は `node tools/test-slots.js` で検証する（24件）。時刻に依存するので、実装を `index.html` から
抜き出したうえで「その時刻だったら」を差し込んで確かめている。

### 6.9 外から開く（iOSショートカット連携）

Webから端末のカレンダーを読むAPIは存在しないので、カレンダー連携はiOS側にやらせる。
アプリはURLパラメータで叩かれるだけ。サーバーもカレンダー権限も要らない。

| パラメータ | 動き |
|---|---|
| `?t=名前` | そのタスクを「いま」欄に出す（ID・完全一致・部分一致の順で探す） |
| `?timer=10` | 10分のタイマーを始める（30秒〜15分に丸める） |
| `?v=dungeon` | そのタブを開く（`clean` / `dungeon` / `gear` / `rec`） |

> **URLでは経験値もゴールドも入れない。**
> 自動化で強くなれてしまうと「掃除しないと強くなれない」という前提が崩れる。
> URLができるのは「開く」「出す」「タイマーを始める」までで、報酬が入るのは必ず本人がタップしたときだけ。
> タイマーだけは走らせてよい——完走しなければ報酬にならないので、実際に手を動かす必要が残るため。

処理後は `history.replaceState` でパラメータを消す。開き直しで二重に走らせないため。

## 8. バランスを変えるときの手順（必須）

> **戦闘の数値・気力の定数・装備の数値・敵のステータスを触るときは、必ず `tools/sim.js` を通す。例外なし。**

```bash
node tools/sim.js
```

シミュレータは装備表・気力の定数・敵データを `index.html` から直接読むので、実装とずれない。
ダメージ式とおまかせAIだけは手で写しているので、`decide()` や式を変えたら**シミュレータ側も同時に直すこと**。

### 見るべき指標

`雑`（ボタンの意味を分かっていない人が「はたく」を連打）と `上手い`（コマンドを使う）の2列を出す。
**バランスは必ず「雑」側に合わせる。** 上手い側だけ見て調整すると初心者が詰む。

### 現在の基準値（2026-08-26）

| 対象 | 雑 | 上手い | 意図 |
|---|---|---|---|
| ストーリーの雑魚 | 67〜98% | 91〜100% | 詰まらない |
| ストーリーのボス4体 | 43〜49% | 77〜88% | **連打だとコイン投げ、コマンドを使えば勝てる** |
| 今日の魔物 | 92〜97% | 95〜99% | 毎日の作業なので軽く |
| 積もった塵 | 90〜100% | — | 復帰した人を跳ね返さない |

ボスの「雑で約45%」は**意図的な教育装置**。ここで一度負けることで、はじめてプレイヤーはコマンドを読む。上げないこと。

深層は「鍛錬N回でB何Fで頭打ちになるか」で見る。現在: 鍛錬0回でB25F、10回でB30F、25回でB35F、50回でB40F、100回でB45F。
鍛錬費が `1.06^n` で伸びるため、B45Fには約56万Gかかる。無限モードとして意図的にこの形にしている。

### 過去にバランスを壊した3回（同じ轍を踏まないために）

1. **装備の強さを実際より高く見積もってシミュレートした** → 中盤の勝率が0〜1%になった。`tools/sim.js` の `TIMELINE`（そのレベルで現実的に買える装備）はこの反省から来ている。
2. **おまかせAIを直したら全部100%になった** → 原因はAIではなく、気力の自然回復で大掃除がほぼ無コストになっていたこと。自然回復を廃止して再調整。
3. **積もった塵を「歯ごたえのある敵」として作った** → 復帰初日に負ける設計になっていた（§6.5）。

## 10. 既知の弱いところ・未解決

レビューを受けるならこのあたりを見てほしい。

- **`index.html` が3289行の単一ファイル。** 分割していないのは、単一ファイルであること自体が「5年後も動く」ための保険だから。ただし戦闘（1760〜2288行）は明らかに大きく、`battle()` の中に描画・AI・タイマー・決着が同居している。ここだけは切り出す余地がある。
- **自動テストがほぼ無い。** 予定の判定だけ `tools/test-slots.js` がある（24件）。それ以外は
  シミュレータ（数値）とブラウザでの手動操作（挙動）頼みで、回帰テストは無い。
- **接辞22種の組み合わせを検証しきれていない。** 代償つき接辞を複数積んだときの極端なビルド（例: 一点集中×3で通常攻撃が死ぬ）は、シミュレータでは見ていない。
- **深層の経済バランス。** 鍛錬費が `1.06^n` なので、ある時点から装備を買う方が常に効率的になる。切り替わり点を計算していない。
- **タスクの汎用性。** 掃除以外（仕事・私用）のタスクも追加できるが、UIの語彙（「ゴミを拾う」「塵界」）が掃除に寄っているので、他用途では世界観が浮く。急ぎではないと判断して保留中。
- **`hist` が70日で切り捨てられる。** 長期の記録は残らない。意図的だが、年単位で使うなら要検討。
